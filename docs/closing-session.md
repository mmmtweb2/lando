# סשן תיקונים אחד לפני בדיקת משה (8.11.2026)

מטרה: לסגור סוף סוף את כל מה שחוסם מסלול לקוח מלא אחד, ורק אותו. משה עובר אחר כך בעצמו את המסלול כלקוח חדש: הרשמה, חיבור כרטיס עסק מאומת, תשלום אמיתי (הלקוח מזין את פרטי האשראי בעצמו בעמוד של סאמיט), והתחלת העבודה.

## כלל הקפאה
- הרשימה למטה סגורה. מה שלא כתוב בה לא נכנס לסשן. כל רעיון, ליטוש או ממצא חדש נרשם ב"אחרי הבדיקה" ולא נעשה עכשיו.
- חריג יחיד: תקלה שחוסמת את המסלול (לקוח לא יכול להמשיך, חיוב שגוי, איבוד נתונים). אותה מתקנים ומדווחים לאבי.
- כל משימה: PR נפרד, tsc + build + npm test, חלק README, הודעה לאבי בצ'אט. PR שנוגע בתשלום, באימות או בקופונים ממתין לאישור משה. השאר ממוזגים על ידי אבי.

## איציק (שרת)
1. **מצב בדיקה לתשלום.** `SEO_TEST_PRICE` + `SEO_TEST_EMAILS` (רשימה מופרדת בפסיקים). רק אימייל ברשימה משלם את הסכום הזה בכל תוכנית, חודשית ושנתית. כבוי כברירת מחדל, ובלי רשימה אין שום השפעה. בדיקה שמוכיחה שמשתמש אחר משלם את מחיר הקטלוג. (נוגע בתשלום: מחכה למשה)
2. **איפוס חשבון הבדיקה.** SQL קצר, לבדיקה ואז לאיפוס, של כל מה שקשור לאימייל אחד: אדמין, user_products, seo_subscriptions, seo_addon_pages, journey, עסקים שמורים. החשבון עצמו לא נמחק. משה מריץ בעצמו.
3. **חיבור כרטיס כשהמשתמש מנהל ולא בעלים.** לוודא בקוד ובאבחון ה-GBP (feat/gbp-diagnosis) שכרטיס שבו אימייל הפיתוח הוא מנהל מופיע ברשימה ושאפשר לבחור אותו. להשיב: האם חשבון Pagey יכול לחבר כרטיס דרך כניסת גוגל של מייל אחר, ואיזה מצב מסך ההסכמה (בדיקה או פרודקשן, האם mmmtweb2 רשום כ-test user).
4. **תשלום אמיתי, בטיחות.** שדות סאמיט להוראת קבע ולפריסה מסומנים לא מאומתים. לכתוב לאבי: מה קורה אם החיוב הצליח אבל ההחזרה אלינו נכשלה (איך מזהים ומתקנים), איך מבטלים ידנית הוראת קבע בסאמיט, ואיפה רואים אירוע חיוב שלא נקלט (seo_subscription_events).
5. **צעדי הלקוח.** רשימה מדויקת מההרשמה ועד הפעלת הקידום בפרודקשן, ומה עלול להיתקע בכל צעד. כולל רשימת משתני סביבה ומיגרציות להרצה (046, 047) בסדר הנכון.

## קובי (לקוח)
1. **דשבורד הקידום v3 כברירת מחדל** לכל חשבון עם מוצר הקידום. `?dash=v2` ו-`?dash=v1` מכבים. בלי שינוי לוגיקה. (ממתין לאישור משה למיזוג)
2. **תיקון טקסט** `first_check.how` ב-`copy.ts`: "עסקים דומים באזור (חציון הביקורות והעסק עם הכי הרבה ביקורות)".
3. **בורר ארבע האפשרויות ב-`/seo-plan`** (#31): חודשי, חודשי + דף, שנתי, שנתי + דף. מחיר סופי כולל מע"מ, חיסכון בשנתי, תנאי ביטול בשנתי (ללא החזר, ביטול חידוש בלבד) לפני התשלום. מידע מ-`GET /api/seo/plans`. עיצוב "מובלט". (נוגע בתשלום: מחכה למשה)
4. **קישור תשלום להעתקה.** אחרי "המשך לתשלום" גם כפתור "העתק קישור" עם הכתובת שחוזרת מ-`POST /api/seo/subscription/start`, כדי שמשה ישלח אותה ללקוח. לבדוק עם איציק שהקישור נפתח מדפדפן אחר ממכשיר אחר.
5. **הסבר הציון** בבדיקת העסק: משפט גלוי ליד הציון כשעסק מעל חציון האזור נמדד מול הגבוה ביותר.
6. **מסך אחרי התשלום:** חזרה מסאמיט, מנוי פעיל, ומעבר להקמה בלי תקיעה, כולל מצב ביטול ומצב כישלון.

## אבי
1. לבדוק ולמזג כל PR (חוץ מאלה שממתינים למשה), ולהעביר למשה את התשלום לאישור עם סיכום של שורה.
2. להריץ את סוכן ה-QA (`docs/qa/QA-AGENT.md`) על הכתובות הציבוריות ועל `?dash=v3&preview=ongoing` לפני שמשה מתחיל, ולתקן רק חסימות.
3. להכין למשה רשימת פריסה אחת: משתני סביבה, מיגרציות, סדר, ומה לבדוק אחרי.

## אחרי הבדיקה (לא עכשיו)
- שאר עיצוב v3: דפי הלקוח הציבוריים, אשף, דפי הנחיתה, ניהול.
- מטמון אימות הטוקן (אחרי נתוני SERVER_TIMING).
- ביקורות דרך Google My Business API (מחכה לגוגל).
- פערי פרימיום א ושאר שיפורים.
- מספר הדפים במנוי, ושאלת תקרת 12 חודשים לדף כלול.
- כל ממצא חדש מהבדיקה של משה שאינו חוסם.

## הגדרת סיום
הסשן נגמר כשכל סעיף למעלה ממוזג או ממתין לאישור משה בלבד, בדיקות עוברות, ורשימת הפריסה מוכנה. אז אבי מעדכן את משה והוא מתחיל.
