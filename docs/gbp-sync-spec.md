# סנכרון מלא מול כרטיס העסק בגוגל (אפיון, 17.11.2026)

מטרה: בעל העסק שולט בכרטיס העסק שלו בגוגל מתוך הממשק שלנו, וכל מה שנעשה אצלנו מגיע לגוגל.
דוגמה שהולידה את הסבב: דף נחיתה שפורסם אצלנו, ובכרטיס בגוגל כתוב "אין אתר".
מקורות ה-API ופרטי המחקר: README חלק 132 (נכתב עם הבנייה).

## עקרונות
1. **כרטיס האמת הוא גם הכרטיס בגוגל.** כל שמירה של שדה נתמך נשלחת לגוגל מיד: קודם `validateOnly`, אחר כך שליחה אמיתית, ואז קריאה חוזרת. כרטיס האמת מתעדכן רק אחרי שגוגל קיבלה את העדכון.
2. **המתג `GBP_WRITEBACK_ENABLED` נשאר המתג הראשי.** כשהוא כבוי, השמירה נשארת אצלנו בלבד והמסך אומר "העדכון נשמר אצלנו. הסנכרון לגוגל עדיין כבוי". אין שום שליחה לגוגל.
3. **לעולם לא מוחקים שדה בגוגל.** ערך ריק אצלנו לא מנקה ערך בגוגל. כל שליחה נושאת רק את השדות שהשתנו (`updateMask`).
4. **שדות זהות (שם, כתובת, קטגוריות, סטטוס פתוח/סגור) לא בסבב הזה.** הם עלולים לגרום לאימות מחדש או להשעיה, והם יגיעו בסבב נפרד עם מסך אזהרה.
5. **מכסה:** גוגל מתירה 10 עריכות בדקה לכרטיס. על 429 מנסים שוב עם השהיה אקראית, עד 3 פעמים, ומדווחים "גוגל עמוסה, ננסה שוב בעוד דקה".
6. כל שינוי שנשלח לגוגל נרשם ביומן הפעולות (`seo_activity`, kind `card_field_synced` / `photo_added` / `photo_removed`), כדי שהדוח החודשי יוכל לספר עליו.

## שלב 1: שדות
שדות שנשלחים לגוגל בסבב הזה, ומסכה לכל אחד:

| שדה אצלנו | שדה בגוגל (updateMask) | הערות |
|---|---|---|
| website | `websiteUri` | https בלבד |
| description | `profile.description` | עד 750 תווים, בלי קישורים ובלי מספרי טלפון (אותה בדיקה כמו בפוסטים) |
| phone (+ עד 2 נוספים) | `phoneNumbers` | ראשי ונוספים נשלחים יחד |
| hours | `regularHours` | |
| specialHours | `specialHours` | חגים וימים מיוחדים: תאריך, סגור או שעות. דורש שעות רגילות |
| services | `serviceItems` | freeForm. כל הרשימה מוחלפת, ולכן תמיד ממזגים עם הרשימה שבגוגל ולא מוחקים פריטים שקיימים שם |

**סטטוס לכל שדה** (מוצג ליד השדה), מחושב מ-`metadata.hasPendingEdits` ומ-`locations/{id}:getGoogleUpdated` (מחזיר `diffMask` ו-`pendingMask`):
- `live`: מה שאצלנו זהה למה שמוצג בגוגל
- `pending`: נשלח, וגוגל עוד בודקת ("ממתין לאישור גוגל")
- `google_changed`: גוגל (או בעל העסק ישירות בגוגל) שינו את הערך. מוצגים שני הערכים ושני כפתורים: "להשאיר את מה שבגוגל" (מאמץ אצלנו) או "להחזיר את שלנו" (שולח שוב)
- `local_only`: הסנכרון כבוי, או שהשליחה נכשלה (עם הסיבה)

## שלב 1: האתר מתעדכן בפרסום הדף
כשהדף של העסק (`businessPageId`) מתפרסם או משנה כתובת:
- אם בגוגל אין אתר: הכתובת הציבורית (`shareUrl`) נשלחת ל-`websiteUri` אוטומטית, וביומן נרשם "הוספנו את הדף שלכם כאתר בכרטיס בגוגל".
- אם בגוגל יש אתר אחר: לא דורסים. בדף הבית מופיעה הצעה "להציג בגוגל את דף הנחיתה במקום <האתר הנוכחי>?" עם כפתור אישור.
- הגדרה בתוך "מה מתפרסם לבד": "קישור הדף בכרטיס בגוגל" (`website_mode`: `auto` כברירת מחדל, `ask`, `off`).

## שלב 1: קריאה שבועית
סריקה שבועית לכל חשבון מחובר וזכאי: קוראת את הכרטיס מגוגל, מעדכנת את הסטטוסים, ושדה שהשתנה בגוגל (ולא אצלנו) מאומץ לכרטיס האמת עם שורה ביומן "עדכנו מגוגל: שעות הפעילות". כך הפוסטים לא כותבים שעות ישנות.

## שלב 2: תמונות
- רשימת התמונות שבגוגל (v4 `media.list`), עם קטגוריה ותמונה ממוזערת.
- העלאה מהממשק: קובץ JPG/PNG/WEBP עד 10MB. השרת ממיר ל-JPEG (sharp), מוודא לפחות 720 פיקסלים בצד הקצר כשאפשר (מינימום 250), שומר בדלי הציבורי ב-Supabase תחת `gbp/<owner-hash>/`, ושולח ל-`media.create` עם `sourceUrl` וקטגוריה: `COVER`, `PROFILE` (לוגו), `EXTERIOR`, `INTERIOR`, `PRODUCT`, `AT_WORK`, `TEAMS`, `ADDITIONAL`.
- מחיקת תמונה (`media.delete`), עם אישור.
- תמונה שגוגל לא אישרה מסומנת "לא אושרה בגוגל".
- הבחירה הנוחה: "להעלות לגוגל את התמונות מדף הנחיתה", כלומר תמונות הדף, מומרות ל-JPEG, בבחירה ידנית.

## API (שרת)
כולם תחת `/api/seo`, עם `requireAuth` + `requireProduct('seo_autopilot')` ומגביל קצב.

| נתיב | מה עושה |
|---|---|
| `GET /gbp/profile` | `{ syncEnabled, location, fields: { [field]: { ours, google, status, error? } }, metadata: { mapsUri, newReviewUri }, websiteSuggestion: { url, current } \| null, checkedAt }` |
| `PUT /gbp/profile/:field` | body `{ value }`. מאמת, שומר, שולח (כשהמתג דלוק), קורא שוב. מחזיר את אובייקט השדה המעודכן. שגיאות: `invalid` (עם הודעה בעברית), `google_rejected` (עם הודעת גוגל), `quota`, `sync_off` (השמירה נשמרה אצלנו) |
| `POST /gbp/profile/:field/resolve` | body `{ keep: 'google' \| 'ours' }`, עבור `google_changed` |
| `POST /gbp/profile/website-from-page` | מאשר את הצעת האתר |
| `GET /gbp/photos` | `{ photos: [{ id, url, thumbUrl, category, createdAt, state }] }` |
| `POST /gbp/photos` | multipart: `file` + `category`, או JSON `{ fromPageImage: url, category }` |
| `DELETE /gbp/photos/:id` | מוחק בגוגל |

## לקוח
- מסך "פרטי העסק" אחרי ההקמה הופך ל"הכרטיס שלכם בגוגל": כל שדה הוא כרטיסייה עם הערך, תג סטטוס ועריכה במקום.
- אזור תמונות באותו מסך: רשת תמונות, כפתור "הוספת תמונה" עם בחירת סוג, ו"מדף הנחיתה".
- הצעת האתר מוצגת בדף הבית בתיבת "מה מחכה לכם".
- פס עליון כשהסנכרון כבוי: "השינויים נשמרים אצלנו. העברה אוטומטית לגוגל תופעל בקרוב."
- עברית ברבים, בלי מונחים טכניים. כל פעולה שנשלחת לגוגל מסבירה "גוגל לפעמים בודקת שינוי עד כמה ימים לפני שהוא מופיע".

## לא בסבב הזה
שם העסק, כתובת, קטגוריות, פתוח/סגור, קישורי פעולה (הזמנה, תפריט) ו-`getExtended` (v1alpha, סיבת דחייה לכל שדה). אזור שירות, מאפיינים של כן/לא והצעת חגים נכנסו בשלב א' (למטה).

## שלב א': אזורי שירות, מאפיינים וחגים (18.11.2026)

השדות הבטוחים בלבד. כל העקרונות למעלה חלים: הכתיבה מאחורי `GBP_WRITEBACK_ENABLED`, לא מוחקים בגוגל, 10 עריכות בדקה לכרטיס עם ניסיון חוזר על 429, ורישום ביומן (`card_field_synced`). לא נדרשת מיגרציה: הנתונים נשמרים בתוך `business_truth.card` ו-`business_truth.google_state` (JSONB שכבר קיימים).

### 1. אזורי שירות (`serviceArea`)
- שדה רגיל במערכת הסטטוסים: `live` / `pending` (לפי `pendingMask` עם `serviceArea`) / `google_changed` / `local_only`. נשלח עם `updateMask=serviceArea`, קודם `validateOnly` ואז שליחה אמיתית וקריאה חוזרת.
- ערך: `{ type, places: string[] }`. בשמירה הלקוח שולח `{ places: string[] }` (שמות בלבד). 1 עד 20 אזורים, שם של 2 תווים לפחות, בלי קישורים ובלי מספרי טלפון. רשימה ריקה נדחית (`invalid`, `serviceArea`) ולא מנקה את גוגל.
- גוגל מקבלת אזור רק לפי Place ID של אזור. שם שכבר ברשימת הכרטיס או בגוגל שומר את ה-ID שלו. שם חדש מחפשים ב-Places API (New, `places:searchText`, אזור ישראל, התוצאה הראשונה מסוג עיר או אזור). שם שלא זוהה: `invalid` עם `field: serviceAreaPlace` ו-`detail` עם השם, ושום דבר לא נשלח. החיפוש רץ רק כשהשליחה לגוגל עומדת לקרות (לא כשהמתג כבוי).
- סוג העסק (`businessType`: `CUSTOMER_AND_BUSINESS_LOCATION` או `CUSTOMER_LOCATION_ONLY`) נשמר בדיוק כפי שהוא בגוגל, ומוצג בלבד. הוא קובע אם הכתובת מוצגת, ולכן לא משנים אותו כאן. אם לכרטיס אין סוג, נבחר הסוג שמתאים לכך שיש כתובת רחוב. כתובת העסק (`storefrontAddress`) לא נכללת בגוף הבקשה לעולם.
- כרטיס שנשמר לפני שלב א' אין בו אזור שירות: בקריאה הראשונה מגוגל הערך של גוגל נקבע כשלנו (בלי לכתוב לגוגל), כדי שהמסך לא יפתח עם התנגשות.

### 2. מאפיינים של כן/לא (`attributes`)
- נקרא: `locations/{id}/attributes` (מה שמוגדר) ו-`attributes.list` עם `categoryName`, `regionCode=IL`, `languageCode=he` (מה קיים לקטגוריה, בשמות בעברית). הרשימה נשמרת שבוע ב-`google_state.attributeMeta`.
- רק מאפיינים מסוג `BOOL`, לא חוזרים ולא מבוטלים, עם שם להצגה. מאפיינים מסוג enum, חוזר או קישור (כולל קישורי תפריט והזמנה) מדולגים בקריאה ובכתיבה.
- נשמר ב-`card.attributes` כ-`{ "attributes/<id>": true | false }`. מאפיין שלא סומן מעולם נעדר. ביטול סימון של מאפיין שהיה מסומן נשלח כ"לא" מפורש, ולא כמחיקה.
- נשלח: `PATCH locations/{id}/attributes?attributeMask=<השמות שנשלחו>`, רק המאפיינים שנבדלים מגוגל, קריאה אחת (עריכה אחת מול המכסה). אין `validateOnly` לקריאה הזו, ולכן סירוב של גוגל מגיע מהשליחה האמיתית והכרטיס אצלנו נשאר כמו שהיה. `attributeMask` תמיד שווה בדיוק למה שנשלח, ואף פעם לא `attributes` כולו.
- סטטוס אחד לכל הקבוצה: `live`, `google_changed`, `local_only`. אין `pending`, כי גוגל לא נותנת איתות כזה למאפיינים. "להשאיר את מה שבגוגל" מאמץ את הערכים של גוגל (מאפיין שגוגל לא הגדירה יוצא מהכרטיס אצלנו ולא נשלח). "להחזיר את שלנו" שולח רק את מה שנבדל.
- קריאה שנכשלה (המאפיינים או רשימת מה שקיים) לא חוסמת שום שדה אחר: נשארים הערכים האחרונים, ליד השדה מופיע משפט, והקריאה הבאה מנקה אותו.

### 3. חגים בשעות מיוחדות
- `src/services/israeliHolidays.ts`: טבלה סטטית ל-2026 עד 2028 (נגמרת ב-31.12.2028), ראש השנה (שני ימים), יום כיפור, סוכות, שמחת תורה, פסח, שביעי של פסח, יום העצמאות (לפי כלל ההזזה), שבועות. חנוכה ופורים אינם ימי סגירה ולא בטבלה.
- `suggestHolidays(now, existingDates, days = 120)`: החגים מהיום ועד 120 יום קדימה, בלי תאריכים שכבר ברשימת השעות המיוחדות.
- ההצעה חוזרת ב-`GET /gbp/profile` כ-`holidays: [{ id, name, date }]`. בלקוח "הוספה כסגור" ממלאת שורה של יום סגור בעורך של השעות המיוחדות, ועוד "הוספת כל החגים". לא נשמר ולא נשלח שום דבר עד שבעל העסק לוחץ "שמירה", והוא יכול לערוך את השורה קודם. השמירה עצמה היא `PUT /gbp/profile/specialHours` הרגיל.

### API (שינויים)
| נתיב | שינוי |
|---|---|
| `GET /gbp/profile` | `fields` כולל `serviceArea`, ו-`attributes` כשיש מה להציג. חדשים: `attributeItems: [{ name, label, group }]` ו-`holidays: [{ id, name, date }]` |
| `PUT /gbp/profile/serviceArea` | body `{ value: { places: string[] } }`. שגיאות: `invalid` (`serviceArea`, `serviceAreaPlace`), `google_rejected`, `quota`, `sync_off` |
| `PUT /gbp/profile/attributes` | body `{ value: { "attributes/<id>": boolean } }`. שמות שגוגל לא מציעה לכרטיס, או ערך שאינו true/false: `invalid` (`attributes`) |
| `POST /gbp/profile/:field/resolve` | `field` יכול להיות גם `serviceArea` ו-`attributes` |

אין נתיבים חדשים: אותם נתיבים, אותו מגביל קצב, אותה בדיקת התחברות ומוצר.

### נתונים
בלי מיגרציה. `business_truth.card` מקבל `serviceArea` (`{ type, places: [{ name, placeId }] }`) ו-`attributes`, ו-`google_state` מקבל `attributeMeta` ושגיאה לכל אחד משני השדות. הקריאה השבועית מאמצת גם אותם (עם שורה ביומן "עדכנו מגוגל").

### לא אומת מול גוגל האמיתי
הכול נבדק מול תשובות מדומות (`scripts/test-gbp-sync-phase-a.ts`). נקודות שדורשות בדיקה אחת על כרטיס אמיתי לפני הפעלה: שדה שם המשאב ב-`attributes.list` (`parent`), שמות התצוגה בעברית, מה גוגל מחזירה ל-`placeName` של אזור, אם Place ID מ-Places API מתקבל כפי שהוא ב-`serviceArea`, ואם `serviceArea` מותר ב-`readMask` של `getGoogleUpdated`.
