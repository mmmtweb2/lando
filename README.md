# Pagey — Engineering README

Pagey (formerly "Lando" / "Tirnoer Digital") is a live, production, Hebrew-first (RTL) SaaS at **pagey.co.il** that auto-generates AI landing pages for Israeli small businesses. This file is the single entry point for any agent joining work on this repo — read this before exploring the codebase; it should save you from re-deriving what's already known.

**Read this file first. Update it before you finish your task**, in the relevant section below. Keep entries short — this file is meant to be read whole, cheaply, not skimmed for the one paragraph that matters.

## Stack

- **Backend**: `src/` — Express + TypeScript (`npm run dev` / `build` / `start`), Postgres via Supabase, `pg` for raw queries.
- **Frontend**: `client/` — React 19 + TypeScript + Vite + Tailwind v4, react-router-dom v7, framer-motion, react-helmet-async. Separate `client/package.json` — build with `cd client && npm run build`.
- **Auth/DB**: Supabase (Postgres + Auth). RLS is enforced on `user_profiles`, `landing_pages`, `leads`, `payments` (see `migrations/007_security_rls_lockdown.sql`, `008_payments_table.sql`).
- **AI text**: Anthropic API (`src/services/ai.service.ts`) — falls back to mock content if `ANTHROPIC_API_KEY` is unset. Prompts include an explicit, itemized anti-fabrication rule (`NO_FABRICATION_RULE`, added 2026-08-31) forbidding invented stats/clients/awards/testimonials — applies to page generation AND the "regenerate this section" AI-edit flow.
- **AI images**: fal.ai (`FAL_KEY`). Stock fallback: Unsplash.
- **Email**: Resend (`src/services/*`, `RESEND_API_KEY`). Lead-notification HTML escapes all visitor-submitted fields (fixed 2026-08-31 — was an HTML-injection vector).
- **Payments**: SUMIT (Israeli provider) — the **real, verified** checkout path is `src/controllers/payment.controller.ts` + `src/services/summit.service.ts` (server-side webhook verification, idempotent), covering both one-off credit packs and the `freelancer`/`agency` yearly plans (`src/config/plans.ts`). There is a separate **mock** checkout (`purchaseCredits` in `user.controller.ts`) used for local/dev testing only — hard-disabled when `NODE_ENV=production` and requires real auth (fixed 2026-08-31).
- **Plans**: `free` / `freelancer` / `agency` (`src/config/plans.ts`). `agency` includes `whiteLabel: true` — this is now actually delivered on the public page (badge + title suffix hidden, fixed 2026-08-31; previously sold but never implemented).
- **Migrations**: plain numbered SQL files in `migrations/`, run manually/via deploy — no migration framework. Read the filenames in order; several are clearly bug-driven patches (e.g. `007_security_rls_lockdown.sql`), which is useful signal for what's broken before.
- **Deploy**: Docker (`Dockerfile`), Node 22 (needed for native WebSocket / Supabase realtime — see `git log` for the docker fix commits).
- **Post-deploy smoke test**: `smoke-test.mjs` at repo root (`node smoke-test.mjs [baseUrl]`). Checks: old-brand-string leaks ("Tirnoer"/"Tirnoer Digital"), dead `localhost` links, empty `<title>`, `robots.txt`/`sitemap.xml` correctness, homepage meta description + `og:title`/`og:image`, malformed `wa.me/` WhatsApp numbers, missing `<img alt>`. **Before reporting a bug in any of these categories, read this file — it may already be guarded.**
- **Known environment quirk**: `cd client && npm run build` currently fails inside the sandboxed dev VM used for this work (`rolldown`/vite native binding missing for `linux-arm64-gnu` — an artifact of `node_modules` being installed for a different architecture than that VM). `npx tsc -b --noEmit` is the reliable correctness check in that environment and was kept clean throughout. Verify a real build in your normal local/CI/Docker environment before deploying — not yet confirmed there.

## Working conventions (read before touching code)

1. **This is a live production app with real users and real money (SUMIT).** Treat every change as a deploy candidate, not a sandbox experiment. No destructive commands, no direct edits to `main`.
2. **Branch per workstream**, name `fix/<slug>` or `feat/<slug>`. Commit locally; **do not push** without explicit sign-off from Moshe (product owner) — payments/auth/security changes especially. Work as of 2026-08-31 lives on branch `dev` (not yet merged to `main`/pushed).
3. **Auth pattern**: never trust `req.body.email` (or any client-supplied identifier) for identity — use `req.authEmail`, set by `requireAuth` (`src/middleware/auth.middleware.ts`) after verifying the Supabase bearer token. `requireOwnPage` additionally checks page ownership or admin. `optionalAuth` (added 2026-08-31) is for public routes that want to *optionally* know the caller's identity (e.g. to compute an `isOwner` flag) without requiring login. Follow this pattern for any new route — this bit the codebase twice (the credits-purchase exploit, and a second unauthenticated-profile-disclosure bug on `POST /api/users/auth`, both fixed 2026-08-31).
4. **Error responses**: return `{ error: message }` (or `{ error, details }`), never `error.stack` or a raw DB error message, to API clients — even on public/unauthenticated routes (`submitLead` was leaking raw Postgres errors until 2026-08-31).
5. **Public endpoints and PII**: don't `select('*')`-and-spread a DB row into a public JSON response without checking every column — `landing_pages.owner_email` was being leaked this way to any visitor on `GET /api/landing/:slug` until 2026-08-31 (now stripped; ownership is exposed as a server-computed `isOwner` boolean instead).
6. **User-submitted content going into HTML** (emails, any future SSR) must be escaped — the lead-notification email was interpolating visitor-submitted fields unescaped until 2026-08-31.
7. **RLS**: any new table needs an explicit RLS policy — check `migrations/007_security_rls_lockdown.sql` for the pattern used on existing tables.
8. **Client-side caches must be re-validated against the current auth identity, not just checked for existence.** `UserContext`'s localStorage-cached profile was reused across different logged-in accounts on a shared browser until 2026-08-31 (`App.tsx`'s `SyncAuth` now compares the cached profile's email to the current Supabase session's email before trusting it).
9. **Before you build a feature**, grep for it — this codebase has had rebrands and leftover legacy code. Don't assume a file that looks relevant is live/current; check what's actually routed/imported. (`ClientPortal.tsx`/`/portal` was exactly this — deleted 2026-08-31, see Fixed.)
10. **Language**: user-facing strings are Hebrew, RTL (`dir="rtl"`). Match this in new UI/error messages.
11. **Content generation and fabrication risk**: the product's core value is AI-written page copy for real businesses. Never let a prompt change relax the no-fabrication guarantee (see `NO_FABRICATION_RULE` in `ai.service.ts`) — no invented stats, client names, dates, awards, or testimonials, ever, even to make copy sound "richer."
12. **Token/cost discipline**: don't re-read the whole repo — this README + targeted `grep`/`Read` of the specific files you're touching is enough for almost every task. Use the Backlog below as ground truth for known issues instead of re-auditing from scratch. For genuinely parallel work by multiple agents, use `git worktree` off `dev` (see e.g. commit history around 2026-08-31) rather than multiple agents editing the same working copy concurrently — symlink `node_modules` (root + `client/`) and `.env` into each worktree rather than reinstalling.

## Strategic roadmap (TPM deep-dive + CEO brainstorm, 2026-08-31)

## Open dilemmas — decisions + research (2026-08-31, part 8)

Moshe made calls on the remaining open items from the strategic roadmap, and asked for research on the rest. Two direct fixes shipped, one repricing agent shipped code, three research briefs delivered (no code) — full findings live in that session's transcript, this is the durable summary.

**Shipped:**
- Draft pages are now 404 for anyone but the owner/admin (`GET /api/landing/:slug`), and the OG-preview shell also refuses to leak draft content into link previews. Previously: fully visible to anyone with the link, only the lead form was blocked.
- Free-tier accounts now have a real monthly page-creation cap (5/month) — closes the abuse surface that survived the credit-mint fix (uncapped creation was still possible, just no longer profitable). Fixed a related bug: the cap function only ever applied to an *active paid* plan, so setting a free-tier number alone would have done nothing; free (and any lapsed paid plan) now correctly falls back to the free tier's own cap.
- **Credit repricing** (new `src/config/credits.ts` / `client/src/config/credits.ts`): costs now track real relative cost — text-section edit 1, full-page text rewrite 6, single image 2, full image set 8, create-time AI images 4 (a deliberate acquisition discount vs. the true 8, documented as the one intentional deviation). Starting grant raised 10→24 (= 1 full image regen + 2 full text rewrites + a small bonus, per Moshe's formula). **New migration `011_credit_repricing.sql` needs to run in Supabase, same as 009/010.** Flagged for Moshe: paid-plan `monthlyCredits` (freelancer 30, agency 150) weren't changed, but now buy ~4x less than before under the new prices — worth revisiting alongside the pricing-tier decision below.

## Renewal lifecycle: reminders, grace, freeze, retention, hard-delete (2026-09-02, part 10)

Closes the gap flagged in part 8/9: `expires_at` was already being stamped on every published page (+1 year) but nothing ever read it — no reminder, no consequence, no way to pay for another year, while the marketing page has been promising "חידוש שנתי — 99 ₪ בלבד" the whole time. Built end-to-end in one dedicated pass (backend + dashboard/viewer UI), merged clean, `tsc` clean both sides.

**Lifecycle**: T-30d/T-7d/T-0 reminder emails (page stays live) → 7-day grace period after expiry (page stays live) → **freeze** (`status:'frozen'`, page taken offline to the public, reuses the exact draft-lockdown pattern) → up to 12 months frozen, restorable any time for ₪99 flat (unchanged price, manual only — no SUMIT standing-order auto-renewal, explicitly out of scope) → **hard delete** (page + its `leads` rows) after 12 months frozen with no renewal. A plain `setInterval` sweep in `src/index.ts` runs every 6 hours (day-granular lifecycle, so hourly is wasted cost; a `node-cron` dependency wasn't needed).

**Frozen-page UX (a judgment call, not directly specified)**: the owner/admin still sees the full page; a stranger gets **410 Gone with a short, friendly Hebrew message** (not a bare 404) — reversible and honest to search engines. The pre-auth OG-preview path (`og.controller.ts`, hit by link-preview bots that can't be told owner from stranger) mirrors `draft` exactly: a generic shell, no exception. A lapsed paid page is a customer's asset, not a work-in-progress secret, so the two layers deliberately differ.

**Payment integrity preserved and extended**: new SUMIT purpose `'renew'` (₪99) added alongside `publish`/`credits`/`bundle`. `grantRenewal` re-checks ownership *and* renewability at grant time (not just at `startPayment`, since the admin force-activate tool reaches the grant directly), and its write is a compare-and-swap on both `status` and `renewal_count` — a double-fire (double-click, or a race with force-activate) can add at most one year off one charge, `false` proves nothing was written, safely retryable. `page_credits` is deliberately never touched by a renewal (99₪ flat fee, not a page-credit purchase) — and the reverse hole was closed too: a frozen page can no longer be "published" via the 249₪ flow or a spent page credit, both now redirect to the 99₪ renewal.

**New expiry = `max(now, current expires_at) + 1 year`** — renewing early (say, off the T-30 email) extends from the *old* expiry so the customer doesn't lose the days still on the clock; renewing a frozen page extends from *now* (generous, matches the "err toward the customer" precedent from parts 8/9).

**Image storage durability (the part-8/9 prerequisite) — fixed going forward**: Supabase Storage was not wired up at all before this round. New `src/services/storage.service.ts` uploads to a public bucket `page-assets` (lazily/idempotently created on first upload, using the existing service-role credentials) and `image.service.ts` now writes there instead of `public/uploads/` on container-local disk. **Per Moshe's explicit instruction, existing/current test uploads were NOT migrated** — only new uploads are fixed. Bucket auto-creation could not be verified end-to-end (no outbound network from the dev shell) — if it doesn't self-create on first real upload, the manual fallback is: Supabase dashboard → Storage → New bucket → name `page-assets`, Public checked, 10MB limit, MIME types `image/webp, image/png, image/jpeg`.

**Before deploy**: run `migrations/013_renewal_lifecycle.sql` in Supabase (adds `frozen_at`, three reminder-sent timestamps, `renewed_at`, `renewal_count`, two indexes — all additive/idempotent, no data changes) **before** deploying the code, since the sweep writes those columns ~30s after boot. Migrations 011 and 012 from parts 8/9 should already be run first if they weren't yet.

**Not done, on purpose**: `ON DELETE CASCADE` on the `leads`→`landing_pages` FK — would make the dashboard's one-click page delete silently destroy lead history as a side effect. The hard-delete sweep instead deletes a frozen page's `leads` rows explicitly, first, and treats a failed leads-delete as a hard stop (page stays frozen, retried next sweep) rather than risking an orphan.

## Legal pages: real Terms/Privacy/Accessibility text + no-refund policy with required acknowledgment (2026-09-06, part 13)

## Bug fixes: sideways-uploaded photos + donation-page CTA defaulting to WhatsApp (2026-09-06, part 15)

Moshe found both bugs live while building a real association (עמותה) page — donation goal, own uploaded photos, own donation link. Both root-caused by direct code inspection (no guessing) and fixed directly, no subagent needed (small, well-isolated, well-understood).

**Sideways photos**: `image.service.ts`'s `processAndSave()` — the one shared function every uploaded logo and photo goes through — ran `sharp(buffer).resize(...).webp(...)` with no `.rotate()` call. Sharp does not auto-orient pixels by the source file's EXIF Orientation tag unless `.rotate()` is called explicitly, and its WebP output strips EXIF metadata by default. So a portrait phone photo (landscape sensor data + an EXIF tag saying "rotate 90°") went in looking correct and came out as a sideways WebP with no metadata left for the browser to correct it with — this is *the* classic cause of "my photo is sideways" bugs industry-wide. Fixed by adding `.rotate()` (no arguments — auto-orient from EXIF, then clear the tag) before `.resize()`, so pixels are corrected once, physically, up front; every downstream consumer (the live page, the OG-tag preview image, thumbnails) inherits the fix automatically, with no per-consumer workaround needed. **Does not retroactively fix already-uploaded sideways images** — those were re-encoded without the orientation tag already baked in wrong; they need to be re-uploaded. Could not run a live pixel-level test of this from this session (the same darwin-arm64/Linux-VM `node_modules` architecture mismatch that blocks `vite` also blocks `sharp`'s native binding here) — the fix follows `sharp`'s standard, long-documented `.rotate()` auto-orient behavior, but Moshe should verify by uploading a real portrait phone photo on his own machine.

**Moshe's broader ask — a manual rotate control in the page editor** — flagged for a product decision rather than built now: the EXIF fix above should silently resolve the overwhelming majority of "sideways image" cases at the source, which makes a manual per-image rotate button a safety net for the rare remaining case (e.g. a source file with EXIF already stripped by some other app) rather than an urgent need. It's also a real feature, not a one-line fix — needs editor UI, a rotate action, and a backend re-encode step. Left for Moshe to prioritize against everything else, now that the root cause is closed.

**Donation-page CTA silently pointing to WhatsApp**: `Wizard.tsx`'s `FormState.cta_type` is hardcoded to `'whatsapp'` at form initialization, and nothing ever changed it based on the chosen page goal. The donation/direct_sale external-link input field *does* show correctly (that's the part 6 fix), and *is* wired correctly once `cta_type==='link'` — but nothing set `cta_type` to `'link'` automatically, so unless the user separately noticed step 4's four-button CTA-target selector and manually clicked "קישור חיצוני", the page's one real action button silently kept opening WhatsApp while the donation link sat there unused. This is an easy trap: filling in "קישור לדף תרומה" reasonably feels like it should be enough. Fixed by tracking whether the user has manually touched the CTA-type selector (`ctaTypeTouchedRef`) and, whenever the page goal changes and the selector hasn't been manually touched, auto-defaulting `cta_type` to `'link'` for donation/direct_sale and back to `'whatsapp'` for goals that don't imply an external link — so the common, unattended path now produces a correctly-wired page, while a deliberate manual choice on step 4 is never overridden. `tsc` clean both sides for both fixes.
